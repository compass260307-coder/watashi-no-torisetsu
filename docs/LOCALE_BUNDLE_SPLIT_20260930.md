# 言語別辞書の配信分離（2026-09-30）

日本語ページに同梱されていた英語・韓国語・インドネシア語の診断と共通UIの辞書を分離した。課金UI本体と日本語の課金文言は初期JavaScriptに残し、購入導線を押してからコードを取得する構成には変更していない。

## 変更範囲

- 診断の50問・表示文言・保存キー・遷移先を言語別設定へ移動。各言語の薄いクライアントコンポーネントから、共通の診断処理に設定を渡す。
- ヘッダー、フッター、ボトムナビ、課金カード、プレビュー、ロック案内などのまとまった辞書を `src/i18n/ui/` に移動。
- 日本語辞書は同期import。外国語辞書は該当言語を初期描画時に取得し、言語別Promiseを再利用する。未選択言語のloaderは実行しない。
- `LocaleUiBoundary` が課金ボタンの操作前に辞書を解決する。辞書の取得失敗には再読み込みUIを表示する。
- `BottomNav` 専用の内側Suspenseを維持し、本文のサーバーレンダリングを保つ。
- 参照されなくなった全言語混在の `paywall-peek-content.ts` を削除。

価格・商品・権限・購入API・診断ロジック・診断文言は変更していない。インドネシア語で従来プレビューを出していなかった項目も従来どおり。既存のインドネシア語プロモーションに使われる日本語プレビューは維持した。

## 検証結果

- TypeScript: エラーなし。
- 変更対象ESLint: エラー・警告なし。
- Next.js 16.2.6 Turbopack本番ビルド: 成功、322ページの静的生成完了。公開アセット参照245件を確認。
- `npm run verify:commerce`: 固定カタログ42チェック成功。
- `npm run verify:en`、`npm run verify:ko`、`npm run verify:id`: 成功。
- 移動前後の辞書比較: 商品・価格・CTA・ヘッダー・フッター・プレビュー等126項目、翻訳文言152項目で差分なし。4言語の診断設定、質問配列、文言関数の結果も一致。
- ブラウザー: 4言語・9画面でHTTP 200、JavaScriptエラー・アセット取得失敗なし。各診断の最初の質問が対象言語で表示され、他の外国語辞書の識別文言が取得JSに含まれないことを確認。
- 4言語のトップで、初期表示後の追加JavaScriptを遮断した状態でも課金モーダルが開き、各言語の固定価格が表示され、Escapeで閉じることを確認。
- 日本語モバイル幅390pxのボトムナビからも、追加JSなしで499円の課金画面を開閉できることを確認。
- JavaScriptを無効にして9画面を再読込し、サーバーから返された本文が表示されることを確認。

再実行できる配信・課金回帰テスト:

```sh
# 別ターミナルで、検証用の本番ビルドを起動しておく。
npm run start -- --hostname 127.0.0.1 --port 3036
node scripts/verify-locale-delivery.mjs
```

Chromeの場所は `CHROME_PATH` で指定できる。テストはlocalhostのみ受け付け、外部通信とAPIへの書き込みを遮断する。実際の決済完了やDB保存は、このUI変更の検証では実行していない。

既存の言語検証スクリプトも移動先へ追従させた。合わせて、比較元ですでに古くなっていたトップ計測コンポーネント、ログインimport、削除済みLINEリンク、メール送信条件の参照を修正した。IDとのページ対称性では、日本語専用の既存2ページだけを明示除外した。韓国語のヘッダー・フッターのタロットリンクと新プレビュー画像は個別に破損を注入した読み取り検証でも失敗を検出した。
