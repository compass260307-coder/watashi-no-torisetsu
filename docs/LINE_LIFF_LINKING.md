# LINE × 診断結果：1タップ連携

## 概要

結果ページの「LINEでAliceと話す」は、次の順に動作する。

1. Web側で `kind = liff` のURL安全な32文字トークンを発行する。
2. 現在の画面から `https://liff.line.me/{LIFF_ID}?code={token}` へ遷移する。
3. `/liff` が `liff.init` とログインを行い、IDトークンを `/api/line/link` へ送る。
4. サーバーはLINEの `POST /oauth2/v2.1/verify` でIDトークンを検証してから、LINE userIdと診断ユーザーを連携する。
5. 成功後はAliceのトークを開ける。

非同期処理の後に新規タブを開くとモバイルブラウザのポップアップ制限に当たりやすいため、LIFFへの遷移は `window.location.assign` を使う。

「うまくいかない場合はこちら」を開くと、`kind = manual` の6桁コード、コピーボタン、友だち追加リンクを表示する。このコードをLINEトークへ送る既存Webhook経路は残す。

## 連携先の切り替え

- LIFF：同じLINE userIdが別の診断ユーザーと連携済みなら、最初のリクエストは `409` と現在の診断日・タイプ名を返す。確認画面で同意した場合だけ `force: true` で再送し、連携先を切り替える。
- Webhook：6桁コードの送信を明示的な意思として扱い、その場で連携先を切り替える。返信は「連携先を新しい診断結果に切り替えました」とする。
- 切り替え前の `user_id` と `linked_at` は `line_account_link_history` に保存する。

`consume_line_link_code` RPCが、競合確認、履歴保存、`line_accounts` のupsert、コード消費を同一トランザクションで行う。使用済み・期限切れ・種別不一致はそれぞれ失敗として扱う。

## コードと冪等性

- DBには既存どおり `code_hash` だけを保存し、平文・暗号化カラムは追加しない。
- `line_link_codes.kind` は `liff | manual`。
- LIFFは24ランダムバイトをbase64url化した32文字、manualは6桁数字。
- 有効期限はどちらも10分。
- 手入力コードの照合は、署名検証済みWebhook内でLINEユーザーごとに1時間8回までに制限する。LIFF連携APIは接続元ごとに1時間30回までに制限する。
- 有効な未使用コードを置き換える再発行は、サーバーの発行レート制限に数えない。初回、使用済み後、期限切れ後の発行は数える。
- DB制約により、同じWebユーザー・同じ種別の未使用コードは同時に1つだけ保持する。
- 同じLINE userIdが消費直後に同じLIFFリクエストを再送した場合、現在の連携先が一致していれば `already_linked` として成功を返す。
- 生のLINE userIdやWebユーザーIDは、連携APIのレスポンス・アプリケーションログ・分析イベントのmetadataへ出さない。連携テーブルと切替監査履歴にだけ保存する。

## 言語と遷移範囲

- LIFFの共通入口は、LINEアプリ内・外部ブラウザのどちらでも `liff.init` 後にログイン状態を確認する。未ログイン時はLINE Loginへ進み、復帰後に連携を再開する。
- `code` が無いLIFFアクセスは既存のリッチメニュー経路を維持する。
- WebからのLINE連携導線は現在日本語画面だけで表示する。韓国語画面では誤って日本向けLINE公式アカウントへ誘導せず、APIとDB自体はユーザーのlocaleに依存しない。

## デプロイ前のLINE Developers設定

LINE Developers ConsoleのLINE Loginチャネルで、次を設定する。

- LIFFエンドポイントURL：`https://www.watashi-torisetsu.com/liff`
- Scope：`openid`（`liff.getIDToken()` に必須）と `profile`
- 同じProvider内のMessaging APIチャネルをリンクする
- 友だち追加オプション：`Aggressive`

友だち追加オプションはコードから制御できないため、Console側の設定が必須。

必要な環境変数：

- `NEXT_PUBLIC_LINE_LIFF_ID`
- `LINE_LOGIN_CHANNEL_ID`
- `LINE_CHANNEL_SECRET`
- `LINE_CHANNEL_ACCESS_TOKEN`
- `ALICE_TRANSFER_CODE_SECRET`（未設定時は既存のサーバー秘密鍵へフォールバック）

## 反映順序

1. `supabase/migrations/20260903090000_line_liff_linking.sql` を本番DBへ適用する。
2. 上記LINE Developers設定と環境変数を確認する。
3. アプリケーションをデプロイする。

アプリケーションを先にデプロイすると、`kind` カラムと `consume_line_link_code` RPCがまだ存在せず、コード発行・連携が503になる。

## 実機確認手順

### iOS / Android 共通：初回連携

1. 未連携の診断結果ページでLINE誘導モーダルを開く。
2. 「LINEでAliceと話す」を1回タップする。
3. LINEが開き、友だち追加確認が表示されることを確認する。
4. 連携完了画面に「連携できました。Aliceに話しかけてみて」が表示されることを確認する。
5. 「Aliceとのトークを開く」を押し、診断結果に応じた会話ができることを確認する。
6. 結果ページを再表示し、「連携済み ✓」とトークボタンになることを確認する。

### 連携先の切り替え

1. 上記LINEを診断Aへ連携した状態で、別の診断Bの結果ページからLIFF連携を開始する。
2. 現在の診断日・タイプ名を含む確認画面が表示され、まだ切り替わっていないことを確認する。
3. 「新しい診断結果に切り替える」を押す。
4. 成功画面とLINEメッセージが切替用文言になり、Aliceが診断Bを参照することを確認する。
5. `line_account_link_history` に診断Aのuser id、以前の `linked_at`、診断Bのuser idが保存されていることを確認する。

### フォールバック

1. 結果ページで「うまくいかない場合はこちら」を開く。
2. 6桁コード、コピー、説明文、友だち追加リンクが表示されることを確認する。
3. コードをLINEトークへ送り、初回連携が成功することを確認する。
4. 別診断の6桁コードを同じトークへ送り、「連携先を新しい診断結果に切り替えました」と返信されることを確認する。
5. 期限切れ、使用済み、LIFF用32文字トークンの手入力で連携できないことを確認する。

### 再タップとエラー

1. LIFFへ移る前に同じタブへ戻るなどして再タップし、新しいコードの発行時に以前の未使用コードが無効化されることを確認する。
2. LIFF初期化・通信を失敗させ、LIFF側の日本語エラー案内が表示されることを確認する。
3. Web側のコード発行を失敗させ、6桁フォールバックから再試行できることを確認する。
