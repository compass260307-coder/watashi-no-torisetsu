# Xピクセル rezdw の直接実装と切り替え

## 実装

- 全ページ共通の既存 `x-pixel` スクリプトに `twq('config','rezdw')` を追加する。`rg1zg` と既存ローダーは維持し、`uwt.js` は1回だけ読み込む。
- 診断保存成功後の本人結果ページで、既存 `tw-rg1zg-rg1zv` と追加 `tw-rezdw-reze3` を送る。既存の10分間有効なタブ内完了マーカーを両イベントで共有し、通常の結果再閲覧・共有リンクからは送らない。
- 既存の決済成功検証APIがStripeから取得した `amount_total` / `currency` を使い、`tw-rezdw-1436v3` を送る。通貨は決済通貨、金額はその通貨の主要単位。既存 `rg1zg` の購入イベント `tw-rg1zg-rg1zz` は従来のJPY対象範囲を維持する。
- 金額・通貨が欠ける場合は固定価格などで補完しない。Xの購入送信はサーバー検証済みの `cs_live_` セッションに限る。
- 各イベントIDと `conversion_id` の組で、既存 `wt_x_sent_v1:` キーを維持する。購入の `conversion_id` はStripe Session ID。両アカウントは独立した送信済み状態を持ち、失敗側だけ再試行できる。
- sessionStorage / localStorage / メモリで再読込・再マウントを抑止し、Web Locks対応ブラウザでは同じconversion_idの処理をタブ間で直列化する。ストレージが全て利用不能な環境ではページ内の重複防止に限定される。端末間の送信抑止やX側の完全な重複排除は保証しない。
- 送信済みは `twq` への受け渡し成功を意味し、X側の受信確認を意味しない。診断マーカーは対象両イベントの受け渡しが成功した後に消費する。

公開コンテナ `GTM-K39CJGCF` の `gtm.js` を読み取り、以下の有効ルールを確認した。管理画面の未公開ワークスペースは確認していない。

| GTM tag_id | 内容 | 公開設定の発火条件 |
| --- | --- | --- |
| 27 | `twq('config','rezdw')` | `gtm.js`（ページ読み込み） |
| 29 | `tw-rezdw-reze3` | `diagnosis_complete` かつホスト `www.watashi-torisetsu.com` |
| 34 | `twq('event','tw-rezdw-1436v3',{})` | `meta_purchase` |

現在のGTM購入タグは金額・通貨・conversion_idを渡していない。サイト直接実装と併存させるとベース・診断・購入の二重送信になる。今回のコードはGTMの他媒体タグや既存dataLayerイベントを変更しない。

## 公開前の必須手順

1. GTM管理画面で tag_id 27 / 29 / 34 と対応するタグを特定し、この3タグを停止または直接実装ページで発火しないよう設定する。他媒体タグは維持する。
2. GTMを公開する。未公開の編集だけでは重複は解消しない。
3. 公開 `gtm.js` に `rezdw` の有効な送信ルールが残っていないことを確認する。追加のコンテナ・未公開変更も管理画面で確認する。
4. 検証済みコードを、リポジトリのリリース方針に従って公開する。GTM停止から直接実装公開までの間はrezdwの計測が途切れるため、切り替え間隔を短くする。
5. 自然に発生した診断・実決済について、Xイベントマネージャーで該当イベントの受信と実金額・通貨を確認する。確認のためのテスト注文・架空の購入イベントは送信しない。

この文書は実装・切り替え手順を記録する。GTM変更・アプリ公開の実施結果とX側の受信確認状況は、リリース記録で別途報告する。

## ローカル検証

`node scripts/x-pixel-regression-test.mjs` は全てのネットワーク・Stripe・DB・広告APIをメモリ上のスタブに置き換える。ローダーの単一性、診断マーカー、アカウント別再試行、再読込、複数タブ、決済金額の主要単位換算、Meta/TikTok送信済み状態からのX計測、テスト決済・不正金額の除外を検証する。外部へのイベント送信も注文作成も行わない。

2026-10-03 JSTの検証結果:

- オフライン回帰テスト: 成功。
- 対象ファイルのESLint、ルートTypeScript (`--noEmit --incremental false`): 成功。
- `npm run verify:commerce`: 44項目成功。商品・価格を変更していない。
- `next build --webpack`: コンパイル・TypeScriptは成功。`/th/preview/quiet-owl__R` の静的生成で `Thai result translation is missing for a source paragraph` により失敗。
- Xの変更を読み込まずに、既存のタイ語コンテンツ関数（自己診断、第二部、深掘り、もしも）を同タイプ・プレビュー用スコアで直接実行し、同じ翻訳不足を再現した。今回の計測変更から独立した未解消事項。本番ビルド全体の成功は確認できていない。
- 既存 `npm run verify:th` は成功するが、今回エラーが出たタイ語コンテンツ関数を実行しないため、上記ビルド失敗の解消確認にはならない。
