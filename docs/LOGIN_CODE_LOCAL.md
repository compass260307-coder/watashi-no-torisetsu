# メール認証コードとローカル確認

## ローカルデモ（既定）

`npm run dev -- --hostname 127.0.0.1`で起動し、`http://127.0.0.1:3000/diagnosis?login=1`を開きます。

- 登録済みの例：`member@example.test`
- 未登録の例：`new@example.test`
- 受信箱：`http://127.0.0.1:3000/dev/login-mail`

メールアドレスを送信するとモーダルが6桁入力に切り替わります。受信箱でコードとメールデザインを確認できます。実メール送信、本番DBの読み書き、実アカウントのログインは行いません。正しいコード／メールボタンは架空の結果プレビューに進みます。再送は60秒後、コードは10分間・一度きりです。デモデータはプロセス再起動で消えます。未登録例にはコードを発行せず、無料診断への案内メールを表示します。

## 実メールを使う場合

明示的に実送信する確認時だけ、`.env.local`に`LOGIN_MAIL_MODE=live`を設定してサーバーを再起動します。実際の送信とDB操作が発生するため、ローカルデモの確認には設定不要です。Productionは常に実送信の経路を使い、受信箱APIは404です。開発時でもloopbackホスト以外ではプレビューを利用できません。

- `LOGIN_CODE_SECRET`があれば利用し、なければ既存のサーバー専用SupabaseキーをHMAC鍵として使います。公開環境変数は使いません。
- 既存`magic_links`の`token`にメール・ランダムchallenge・6桁コードのHMACを保存します。コードそのものはDB保存しません。`otp_`の接頭辞で従来のメールリンクと区別します。
- 既存の共有レート制限RPCが機能しない場合は、新しいコード認証経路を停止します。IP・メール・challenge単位で試行を制限します。challengeの試行制限は既存RPCの固定窓方式です。
- 登録済み・未登録とも同じJSON形式と6桁画面です。未登録メールには無料診断の案内のみ送ります。
- コードとメール内リンクは同じtokenを使い、既存の完了ルートで一度だけ消費します。アカウント切り替え確認と結果への遷移も既存処理を使います。
- 再送は従来のGoogleリンクを失効させず、コード用リンクのみを無効化します。
- テーブル追加・migration・DB適用・本番デプロイはありません。実送信と既存アカウントの復元は本番反映前に別途確認が必要です。

## 検証

`node --experimental-strip-types scripts/login-code-test.mjs`

ローカルでコードの発行・誤入力・成功・再利用不可・有効期限・再送・未登録者向けテンプレート・Productionでのデモ非公開を検証します。
